<objective>
## Goal
Stand up a runnable IMGMAN desktop skeleton: Electron + React + TypeScript + Vite with hot reload, a typed IPC bridge (renderer ↔ main), an embedded SQLite database that initializes the schema on first run, and an `electron-builder` config that produces an installable test build.

## Purpose
This is the foundation every later phase builds on. PROJECT.md commits to Electron with a typed-IPC boundary, SQLite metadata, and worker-friendly architecture. Getting the skeleton, the IPC contract, and native-module (better-sqlite3) packaging correct now prevents costly rework once import, grid, and search land on top.

## Output
- A scaffolded `electron-vite` project that launches a window with `npm run dev` and hot-reloads renderer changes.
- A typed IPC channel proven end-to-end (renderer calls main, gets a response).
- `metadata.db` created in userData on launch with the items/folders/tags/smart_folders schema + FTS applied via migration.
- `electron-builder.yml` producing a Windows test build (`npm run build` → unpacked/installer) with better-sqlite3 rebuilt for Electron.
</objective>

## AC-1: App launches with hot reload
```gherkin
Given a clean checkout with dependencies installed
When the developer runs `npm run dev`
Then an Electron window opens rendering the React App
And editing src/renderer/src/App.tsx updates the window without a full restart
```

## AC-2: Typed IPC round-trips
```gherkin
Given the app is running
When the renderer invokes the typed `app:getVersion` (or `ping`) channel exposed via contextBridge
Then the main process handles it and returns a value
And the renderer displays that value, with no use of remote/nodeIntegration in the renderer
```

## AC-3: SQLite initializes schema on first run
```gherkin
Given no existing library database
When the app starts
Then a SQLite file is created under app.getPath('userData')
And the items, folders, item_folders, tags, item_tags, smart_folders tables and items_fts virtual table exist
And starting a second time does not error or duplicate tables (idempotent migration)
```

## AC-4: Production build is produced
```gherkin
Given the project builds cleanly
When the developer runs the type-check and `npm run build`
Then electron-builder produces a Windows artifact (unpacked dir or installer)
And better-sqlite3 is rebuilt against the Electron ABI so the packaged app opens the DB without a native-module error
```

<objective>
## Goal
Build the import pipeline for the active library: bring assets in via drag & drop (files and folders), clipboard paste (image data), and bulk folder import (dialog). For each asset, copy the untouched original into the per-item folder layout, generate a real thumbnail for images/GIFs (sharp) — generic handling for everything else — insert an `items` row, and write a portable per-item `metadata.json`. Surface live progress and the library's item count in the gate UI.

## Purpose
Import is the "Collect" half of the core promise (collect → organize → search → browse). Plan 02-01 established the active-library seam and per-library DB; this plan fills that library with real content and the on-disk per-item layout (root PROJECT.md §6) that Phase 3's grid and Phase 4's search read from. Without import there is nothing to browse or search.

## Output
- `ImportService` in main: source-agnostic engine that takes file paths (or an image buffer), classifies type, copies original to `images/<id>/original.<ext>`, generates `thumbnail.webp` (images/GIFs), writes per-item `metadata.json`, and inserts the `items` row.
- `sharp` added as a dependency for image thumbnails + dimensions.
- Typed `import:*` IPC (drop paths, clipboard paste, bulk folder dialog) with batch progress events, plus an `items:count` query.
- Renderer import UI: a drop zone, clipboard paste, "Import folder…" button, batch progress, and a live item count replacing the "0 items" placeholder.
</objective>

<acceptance_criteria>

## AC-1: Drag & drop files and folders
```gherkin
Given a library is active
When the user drops one or more files (and/or folders) onto the import zone
Then each supported file is copied into images/<itemId>/original.<ext> inside the active library
And dropped folders are walked recursively so their files are imported too
And an items row is inserted per file and the visible item count increases by the number imported
And the original source files on disk are left unmodified
```

## AC-2: Paste image from clipboard
```gherkin
Given a library is active and the clipboard contains image data
When the user triggers paste (Ctrl/Cmd+V on the import zone or a "Paste" button)
Then a new item is created from the clipboard image with a generated thumbnail.webp and an original.png
And an items row is inserted (type=image, source_url=null) and the count increases by 1
And if the clipboard has no image, a clear "no image in clipboard" message is shown and nothing is imported
```

## AC-3: Bulk folder import with progress
```gherkin
Given a library is active
When the user clicks "Import folder…", picks a folder, and confirms
Then all supported files under that folder (recursively) are imported in one batch
And batch progress (done / total) is shown in the UI while it runs
And a single unreadable or unsupported file is skipped (logged) without aborting the rest of the batch
```

## AC-4: Correct per-item layout, thumbnails, and metadata
```gherkin
Given any successful import of an image file
When the import completes
Then images/<itemId>/ contains original.<ext>, thumbnail.webp, and metadata.json
And the items row has id, name, ext, type=image, size_bytes, width, height, created_at, imported_at populated
And for a non-image type (e.g. mp4/pdf/ttf) the original + metadata.json are written, type is classified correctly, no thumbnail.webp is produced, and the row still inserts (width/height/duration_ms null)
```

  <name>Task 1: Import engine — sharp, type classification, copy + thumbnail + row insert</name>
  <files>package.json, src/main/services/import.ts, src/main/services/items.ts</files>
  <action>
    Add the dependency and build the source-agnostic import engine.
    - package.json: add "sharp" to dependencies (latest 0.x). Native module like better-sqlite3 — the existing postinstall (`electron-builder install-app-deps`) rebuilds it for Electron. After editing, run `npm install` so sharp is present for typecheck/dev.
    - src/main/services/import.ts:
      • `classifyType(ext): 'image'|'video'|'audio'|'font'|'doc'|'other'` and an extension→type map. image: jpg,jpeg,png,gif,webp,bmp,tiff,svg,avif,heic. video: mp4,mov,webm,mkv,avi,m4v. audio: mp3,wav,flac,ogg,aac,m4a. font: ttf,otf,woff,woff2. doc: pdf. else 'other'.
      • `genId()` using Node's built-in `crypto.randomUUID()` (no new dep). IDs are stable + unique per PROJECT.md §6.
      • `importFile(absPath): ImportedItem` — read stats; compute id, ext (lowercased, no dot), type, name (basename); create `images/<id>/` under `imagesDir(getActiveLibrary().path)`; copy the source file to `original.<ext>` (copyFile — never move/modify the source); if type==='image', use sharp to read metadata (width/height) and write `thumbnail.webp` (resize to fit within 512×512, `withoutEnlargement`, webp quality ~80); write `metadata.json` (the full per-item record); INSERT the items row via `getDb()` (id,name,ext,type,size_bytes,width,height,duration_ms=null,palette=null,rating=0,source_url=null,note=null,created_at=birthtime ms,imported_at=now). Wrap each file so a single failure throws an Error the caller can collect — do NOT let it abort a batch.
      • `importImageBuffer(buf, suggestedName?): ImportedItem` — same flow for clipboard data: original.png written from the buffer, sharp thumbnail + dimensions, type=image, source_url=null.
      • `importPaths(paths: string[], onProgress?): {imported: ImportedItem[]; failed: {path,error}[]}` — for each path, if it is a directory walk it recursively (skip dotfiles/hidden + node_modules-style noise is unnecessary here; just gather files), flatten to a file list, then import each, calling onProgress(done,total) after each. Collect failures instead of throwing.
      • Prepare INSERT statements once (better-sqlite3 prepared statement); reuse across the batch.
    - src/main/services/items.ts: `countItems(): number` via `SELECT count(*) FROM items` on getDb(); guard when no DB is open (return 0).
    Avoid: moving/renaming/modifying source originals; blocking the event loop (use sharp's async API and fs/promises; sharp's libvips work runs off the JS thread); hardcoding the library path (always resolve via getActiveLibrary()).
  </action>
  <verify>Temp-dir scratch check (or during checkpoint): importFile on a sample PNG creates images/<id>/{original.png,thumbnail.webp,metadata.json} and a row with width/height set; importFile on a sample .pdf/.ttf creates original+metadata.json, no thumbnail, type correct, row inserts; a missing path is reported in `failed` and does not throw. `npm run typecheck` passes with sharp installed.</verify>
  <done>AC-4 satisfied (layout, thumbnail, metadata, row fields for image and non-image); engine foundation for AC-1/2/3.</done>

<objective>
## Goal
Implement the portable `.library` format and its lifecycle: create a new library, open an existing one, switch between recents, with exactly one library active at a time. Refactor the database layer (built in Phase 1 against a fixed userData path) to open `metadata.db` inside the active library folder.

## Purpose
Everything in the MVP — import, grid, search — operates on "the active library." PROJECT.md commits to a self-contained, portable library folder the user owns and can move/back up. Establishing the on-disk format and the open/create/switch flow now is the seam Plan 02-02 (import) and Phases 3–4 build on.

## Output
- A `LibraryService` in main that creates/opens/validates a `<name>.library/` folder (metadata.db, settings.json, images/, thumbnails-cache/).
- DB layer opens per-library instead of a fixed userData path.
- App-level config (in userData) persisting the recent-libraries list and last-opened library.
- Typed IPC (`library:*`) + a minimal renderer "gate" UI to create/open/switch and show the active library.
</objective>

<acceptance_criteria>

## AC-1: Create a new library
```gherkin
Given the app is running with no active library
When the user chooses "Create Library", picks a parent folder, and names it
Then a `<name>.library/` folder is created containing metadata.db (with the full schema), settings.json, an images/ dir, and a thumbnails-cache/ dir
And that library becomes the active library
And the renderer shows the active library's name and path with an item count of 0
```

## AC-2: Open an existing library
```gherkin
Given a valid `.library` folder exists on disk
When the user chooses "Open Library" and selects that folder
Then its metadata.db is opened (schema migration is a no-op on the already-initialized DB)
And it becomes the active library shown in the UI
And selecting a folder that is not a valid library shows a clear error and does not change the active library
```

## AC-3: Recents persist and switch
```gherkin
Given the user has created/opened one or more libraries
When the app is restarted
Then the previously opened libraries appear in a "recent libraries" list
And the last-active library is reopened automatically (or offered) on launch
And choosing a different recent switches the active library (old DB connection closed, new one opened)
```

## AC-4: One active library, DB scoped to it
```gherkin
Given a library is active
When code calls getDb()
Then it returns the connection for the active library's metadata.db (not a userData-global DB)
And switching libraries closes the previous connection before opening the next (no leaked handles / WAL on the wrong file)
```

  <action>
    Define the on-disk format and make the DB open per-library.
    - Refactor src/main/db/index.ts: change initDatabase() to openDatabase(dbPath: string) that opens metadata.db at an explicit path, applies pragmas (WAL, foreign_keys) and the idempotent schema, and stores it as the active connection. Keep getDb()/closeDatabase(); closeDatabase must fully release the handle so a different file can be opened next.
    - Create src/main/services/library.ts with:
      • LIBRARY_DIR_SUFFIX = '.library'; helpers for the paths inside a library (dbPath, settingsPath, imagesDir, thumbsCacheDir).

      • openLibrary(libraryPath): validate it looks like a library (dir exists, metadata.db present OR settings.json present), close any current DB, open this one, set active. Throw a descriptive error if invalid.
      • getActiveLibrary(): { path, name } | null. closeActiveLibrary().
    Avoid: leaving the previous DB open when switching; hardcoding userData as the DB location anywhere.
  </action>

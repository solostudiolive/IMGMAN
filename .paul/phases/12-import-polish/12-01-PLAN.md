<objective>
## Goal
Polish the import pipeline surface after Phase 10 (real media thumbnails) and Phase 11 (URL import) land: expose the existing media-thumbnail backfill through a Settings UI, and surface `duration_ms` on media items in the list view.

## Purpose
Phase 10 added real thumbnails for video/audio/pdf/font and a `items:backfillMediaThumbnails` IPC — but there is no user-facing button to run it (SettingsModal's Library maintenance section only exposes "Extract colors"). List rows show `width×height` but never `duration` for media. These are small, high-signal gaps that complete the import feature set for v1.1 — nothing speculative, nothing structural. (ImportZone error handling was inspected and is acceptable as-is — see Gap #2 below.)
</objective>

## Concrete gaps this plan closes (from code inspection)

1. **No UI for media-thumbnail backfill.** `src/main/services/items.ts:283` `backfillMediaThumbnails()` + `src/main/ipc/items.ts:63` handler + `src/preload/types.ts:184` expose exist, but `SettingsModal.tsx` only has "Extract colors" (palettes) and "Find duplicates". A user who imported media before Phase 10 cannot backfill thumbnails without the Settings button. This directly satisfies Phase 10's AC-6 ("Backfill IPC available") and Phase 11's verification item ("Backfill IPC populates thumbnails for pre-existing media items").

2. **ImportZone error handling was inspected — NO changes needed.** `ImportZone.tsx` `run()` correctly catches errors into `setError` (line 48–49) and `statusLine` (line 180–192) renders `import-status--error`. The logic is sound; the compact strip surfaces errors in the lower-right as designed. This plan does **not** alter ImportZone — Gap #2 is documented here only so reviewers know it was checked and deliberately left alone. (The Phase 11 boundary's "missing catch block" note was a pre-implementation concern that the shipped code already resolves.)

3. **List view never shows `duration_ms`.** `Grid.tsx:352` `ListRow` renders `dims = width×height` but a media item (video/audio) with no width/height (thumbnail extraction failed) shows `—` with no duration signal. `Inspector.tsx:117` already computes `duration` and shows it at line 283; the list row should mirror that for non-image media so the grid and inspector agree.

## AC-1: Media-thumbnail backfill exposed in Settings
```gherkin
Given a library with video/audio/font/doc items that have width IS NULL (no thumbnail yet)
When the user opens Settings → Library maintenance → "Extract media thumbnails for existing items"
Then a backfill runs via items:backfillMediaThumbnails
And on completion the button label returns to idle and a "Done — N updated" caption appears
And failed items are skipped (no crash, no partial state)
```

## AC-2: List row shows duration for media items
```gherkin
Given an imported video item with duration_ms populated
When the user switches the grid to List view
Then the list row shows the duration formatted as mm:ss (e.g. "2:04") alongside the dims/size meta columns
And when width/height are null but duration is present, the dims column shows the duration instead of "—"
```

## AC-3: Backfill is idempotent and safe
```gherkin
Given the backfill has already run on all media items
When the user clicks "Extract media thumbnails" again
Then the IPC returns 0 (no rows match width IS NULL)
And no thumbnail.webp files are overwritten or deleted
```

<objective>
## Goal
Replace the OS window frame with a **chrome-less custom title bar** matching Eagle: a slim
(`--titlebar-h`) themed bar carrying the app name and custom **minimize / maximize-restore /
close** controls, a draggable region, and double-click-to-maximize. Window controls are
driven by a new typed `window:*` IPC namespace, and the maximize/restore icon reflects the
live window state.

## Purpose
Eagle's identity is a borderless, fully-themed desktop shell. The native title bar breaks
the dark look and wastes vertical space. This plan removes it and gives the renderer
ownership of the window chrome — the frame the three-pane shell (Plan 05-03) sits inside.

## Output
- Frameless `BrowserWindow` (Windows/Linux) / `titleBarStyle: 'hidden'` with inset traffic
  lights (macOS), wired to emit maximize-state changes
- New `window:*` IPC (minimize, toggleMaximize, close, isMaximized) + `maximizeChanged` event
- `platform` exposed on the preload bridge so the renderer adapts to macOS
- A token-based `<TitleBar>` React component, integrated at the top of `App`
</objective>

## Established patterns to follow
- IPC: every channel in src/main/ipc/* has a matching typed wrapper in src/preload/index.ts,
  and the shape lives in src/preload/types.ts (IpcApi). Request/response uses invoke/handle;
  main→renderer events use webContents.send + ipcRenderer.on (see import:progress / onProgress).
- Tokens only: components reference var(--color-*) / var(--titlebar-h), never raw hex
  (the close-button hover may use the Windows-red affordance via --color-danger).

## AC-1: Frameless window with a themed custom title bar
```gherkin
Given the app launches on Windows
When the window appears
Then there is no native OS title bar
And a custom title bar of height var(--titlebar-h) is shown at the very top

```

## AC-2: Window controls operate the window
```gherkin
Given the custom title bar is visible
When the user clicks Minimize / Maximize / Close
Then the window minimizes / maximizes / closes respectively
And dragging the bar's empty region moves the window
And double-clicking the bar's empty region toggles maximize/restore
And interactive controls are click-through-safe (no-drag), not part of the drag region
```

## AC-3: Maximize/restore state is reflected live
```gherkin
Given the window is not maximized
When it becomes maximized (via the button, double-click, or OS snap/Win+Up)
Then the maximize control switches to a "restore" icon
And when it is un-maximized the icon switches back
And the state is correct on initial render (queried via window:isMaximized)
```

## AC-4: macOS path is correct (code-verified; runtime unverified per project)
```gherkin
Given the app is built for macOS (process.platform === 'darwin')
When the window is created
Then titleBarStyle 'hidden' is used with inset traffic lights (not frame:false)
And the renderer reserves space for the traffic lights and does NOT render the custom
    min/max/close buttons (the OS draws them)
```

## AC-5: No regressions
```gherkin
Given the new chrome is in place
When `npm run typecheck` and `npm run build` run

And the window remains resizable from its edges
```

    - ipcMain.handle('window:close', (e) => win?.close())
    - ipcMain.handle('window:isMaximized', (e) => win?.isMaximized() ?? false)
    Each returns void/boolean; guard against a null window.

    Register it in `src/main/ipc/index.ts` by importing and calling `registerWindowIpc()`
    alongside the other register* calls.
    Avoid: exposing raw ipcRenderer; capturing a stale BrowserWindow; removing autoHideMenuBar.
  </action>
  <verify>npm run typecheck:node passes; grep src/main/ipc/window.ts for the four window: handlers; index.ts spreads frame/titleBarStyle by platform and wires maximize/unmaximize.</verify>

<task type="auto">
  <name>Task 2: Typed window bridge + platform on the preload api</name>
  <files>src/preload/types.ts, src/preload/index.ts</files>
  <action>
    In `src/preload/types.ts`, extend `IpcApi`:
    - add `platform: string` (the OS platform string, for renderer branching)
    - add a `window` namespace:
        window: {
          minimize: () => Promise<void>
          toggleMaximize: () => Promise<void>
          close: () => Promise<void>
          isMaximized: () => Promise<boolean>
          // main→renderer event; returns an unsubscribe fn (mirrors import.onProgress)
          onMaximizeChange: (cb: (isMaximized: boolean) => void) => () => void
        }

    In `src/preload/index.ts`, implement them on the `api` object:
    - `platform: process.platform` (a plain string value; contextBridge clones it)
    - window.minimize/toggleMaximize/close/isMaximized → ipcRenderer.invoke('window:...')
    - window.onMaximizeChange(cb): attach an ipcRenderer.on('window:maximizeChanged', listener)
      that calls cb(isMaximized); return a cleanup that removeListener's it (same shape as
      the existing import:progress subscription).
    No change needed to src/preload/index.d.ts (it re-exports IpcApi).
    Avoid: typing platform as NodeJS.Platform (renderer tsconfig may lack node globals) — use string.
  </action>
  <verify>npm run typecheck passes (node + web); window.api.window.* and window.api.platform are typed in the renderer.</verify>
  <done>AC-2/AC-3 plumbing exposed to the renderer; types stay in sync with handlers.</done>
</task>

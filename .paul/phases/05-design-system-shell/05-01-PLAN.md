<objective>
## Goal
Establish the renderer-side **design-token + theming foundation** for the v1.0 Eagle
redesign: a CSS custom-property token system with Eagle-matched **dark (default)** and
**light** palettes, a `ThemeProvider` that applies and persists the active theme with no
flash-of-unstyled-content (FOUC), and a global base stylesheet (reset, typography, themed
scrollbars). Prove it end-to-end by re-skinning the existing `App` chrome with tokens and a
temporary theme toggle.

## Purpose
Every later Phase 5–9 plan (title bar, three-pane shell, masonry grid, inspector, context
menus, settings screen) consumes these tokens. Centralizing color/spacing/typography in one
token set is the milestone constraint ("theming via tokens — no hard-coded colors in
components; both themes from one token set") and is what makes a true Eagle dark look
possible without rewriting every component twice.

## Output
- `src/renderer/src/styles/tokens.css` — semantic design tokens (light default + dark override)
- `src/renderer/src/styles/base.css` — reset, html/body, typography, themed scrollbars/selection
- `src/renderer/src/theme/theme.ts` — theme types + localStorage read/apply helpers (FOUC-safe)
- `src/renderer/src/theme/ThemeProvider.tsx` — context provider + `useTheme()` hook
- `src/renderer/src/main.tsx` — apply stored theme pre-render; import styles; wrap `<App/>`
- `src/renderer/src/App.tsx` — top-level chrome converted to tokens + temporary theme toggle
</objective>

## Key constraints discovered
- No global CSS exists today; all components use inline styles.
- CSP in `src/renderer/index.html` is `default-src 'self'; style-src 'self' 'unsafe-inline'; …`
  — there is **no `script-src`**, so inline `<head>` scripts are BLOCKED. The no-FOUC theme
  application must therefore run from a `'self'` ES module (top of `main.tsx`), NOT an inline
  `<script>`. Do **not** weaken the CSP. `style-src 'unsafe-inline'` stays (inline styles
  still exist in not-yet-rebuilt components).
- Theme is an app-level (not per-library) preference. For this plan its source of truth is
  `localStorage` (renderer-owned, synchronous → no FOUC). The Settings screen (Plan 05-04)
  will read/write the same preference via `useTheme()`; a main-process settings store is out
  of scope here.
</context>

<acceptance_criteria>

## AC-1: Token system with dark default + light
```gherkin
Given the app loads with no stored theme preference
When the renderer mounts
Then document.documentElement has data-theme="dark"
And computed CSS custom properties (e.g. --color-bg-app, --color-text, --color-accent)
    resolve to the Eagle-matched dark palette
And switching data-theme to "light" resolves the same token names to the light palette
```

## AC-2: Theme applied, persisted, and FOUC-free
```gherkin
Given the user selects the light theme via the temporary toggle
When they reload the window
Then the app renders in light theme immediately on first paint (no dark flash)
And localStorage key "imgman.theme" equals "light"
And useTheme() reports theme "light"
```

## AC-3: System preference + reactivity
```gherkin
Given the theme preference is "system"
When the OS color-scheme is dark (prefers-color-scheme: dark)
Then the resolved theme is dark
And if the OS color-scheme changes while the app is open
Then data-theme updates live without a reload
```

## AC-4: Existing UI re-skinned via tokens (smoke test)
```gherkin
Given the dark theme is active
When the app shell renders (App heading, footer, and the temporary toggle)
Then those elements use token-based colors (no hard-coded hex in App.tsx top-level chrome)
And the window background, default text color, and scrollbars reflect the dark palette
And `npm run typecheck` passes with no new errors
```

<task type="auto">
  <name>Task 2: ThemeProvider, useTheme hook, and FOUC-safe pre-render apply</name>
  <files>src/renderer/src/theme/theme.ts, src/renderer/src/theme/ThemeProvider.tsx, src/renderer/src/main.tsx</files>
  <action>
    `theme.ts`:
    - export type ThemePreference = 'dark' | 'light' | 'system'
    - export type ResolvedTheme = 'dark' | 'light'
    - const STORAGE_KEY = 'imgman.theme'; DEFAULT_PREFERENCE: ThemePreference = 'dark'
    - readPreference(): ThemePreference — read localStorage, validate, fall back to default
    - systemTheme(): ResolvedTheme — matchMedia('(prefers-color-scheme: dark)').matches
    - resolveTheme(pref): ResolvedTheme — 'system' → systemTheme(), else pref
    - applyTheme(resolved): set document.documentElement.dataset.theme = resolved
    - applyStoredTheme(): applyTheme(resolveTheme(readPreference())) — call at module load

    `ThemeProvider.tsx`:
    - React context exposing { preference, resolved, setPreference }
    - State seeded from readPreference(); on mount and whenever preference changes, compute
      resolved and call applyTheme; persist preference to localStorage on change.
    - Subscribe to matchMedia change events; when preference === 'system', update resolved
      live (AC-3). Clean up the listener on unmount.
    - export function useTheme() that throws if used outside the provider.

    `main.tsx`:
    - At the TOP of the module (before ReactDOM.createRoot), import './styles/tokens.css',
      './styles/base.css', and call applyStoredTheme() so data-theme is set before first
      paint (CSP forbids an inline <head> script — this module runs as 'self').
    - Wrap <App/> in <ThemeProvider>.
    Avoid: applying theme only inside a useEffect (causes a dark/light flash on load).
  </action>

<objective>
## Goal
Give the theme control its permanent home: a **Settings modal** with an **Appearance** section
(Dark / Light / System segmented control) and an **About** section (app version + platform),
reachable from a gear button. Remove the temporary `ThemeToggle` cycle button placed in the
sidebar footer by Plan 05-03.

## Purpose
Closes Phase 5 (Design system & shell): the visual foundation now includes a real settings
surface, not a stop-gap toggle. PROJECT.md lists "settings screen" as a V1 deliverable; the
theme system (05-01) was always intended to land its UI here.

## Output
- `SettingsModal` component (+ CSS): accessible overlay, Appearance (theme) + About sections
- `LibraryGate` wires a gear entry point (sidebar footer + welcome screen) and renders the modal
- `ThemeToggle.tsx` deleted (its job moves into Settings → Appearance)
</objective>

<acceptance_criteria>

## AC-1: Settings opens and closes
```gherkin
Given the app is running (library open OR the no-library welcome)
When the user clicks the gear / "Settings" entry point
Then a centered Settings modal opens over the app
And clicking the backdrop, pressing Escape, or clicking the × button closes it
And while the modal is open it does not trigger the grid's Space quick-preview or other shortcuts
```

## AC-2: Appearance controls the theme (live + persisted)
```gherkin
Given the Settings modal is open
When the user picks Dark, Light, or System in the Appearance control
Then the app re-themes immediately and the control reflects the active preference
And when "System" is selected the resolved theme (dark/light) is shown
And the choice survives an app reload (persisted via the existing theme storage)
```

## AC-3: About shows version and platform
```gherkin
Given the Settings modal is open
When the About section renders
Then it shows the app name, the version from window.api.getVersion(), and the platform
```

## AC-4: Temporary ThemeToggle is gone
```gherkin
Given Plan 05-03 left a temporary dark/light/system cycle button in the sidebar footer
When this plan completes
Then that ThemeToggle button no longer appears anywhere
And ThemeToggle.tsx is deleted with no remaining imports
And the only way to change the theme is the Settings → Appearance control
```

## AC-5: No regressions
```gherkin
When `npm run typecheck` and `npm run build` run
Then both pass with no new errors
And all existing functionality (folder filter, search, import, selection→inspector, edits,
     Space preview when the modal is closed) works as before
```

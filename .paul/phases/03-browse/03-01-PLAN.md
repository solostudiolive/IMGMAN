<objective>
## Goal
Make the active library's items browsable: serve thumbnails/originals to the sandboxed renderer via a custom `imgman://` protocol, expose an `items:list` query, and render every item in a virtualized thumbnail grid that scrolls smoothly at tens of thousands of items. Clicking a thumbnail selects it (selection state is the seam Plan 03-02's inspector + quick-preview build on). Thumbless types (video/audio/pdf/font/other) show a type-based placeholder.

## Purpose
This is the "Browse" half of the core promise. Phase 2 fills the library with items rows + per-item `thumbnail.webp`; nothing yet displays them. The grid is the primary surface of the app and the performance-critical one (PROJECT.md §9: 60fps scroll, <0.5s render at 50k). Establishing the data-access path (list query + local-file protocol) and a windowed grid now is what the inspector (03-02) and search/filter (Phase 4) render into.

## Output
- A privileged `imgman://` protocol (main) that serves `thumbnail.webp` and `original.<ext>` strictly from inside the active library folder.
- `items:list` IPC returning the active library's item rows (typed `Item[]`), newest first.
- A virtualized `Grid` (react-virtuoso `VirtuosoGrid`) rendering thumbnails with placeholders for thumbless types, click-to-select, and an empty state.
- Grid refreshes after an import; switching libraries shows the new library's items.
</objective>

<acceptance_criteria>

## AC-1: Grid renders the library's items
```gherkin
Given a library is active with N imported items
When the active-library view loads
Then a thumbnail grid renders one cell per item, ordered newest-first (imported_at desc)
And image items display their thumbnail.webp
And when the library has 0 items an empty state is shown instead of a blank grid
```

## AC-2: Virtualized — smooth at scale
```gherkin
Given a library with many items (hundreds+)
When the user scrolls the grid
Then only the visible (plus a small overscan) cells are mounted in the DOM, not all N
And scrolling stays smooth (no full-list mount, no layout thrash)
```

## AC-3: Thumbless types show a placeholder
```gherkin
Given items whose type has no thumbnail (video, audio, font, doc, other)
When they render in the grid
Then each shows a type-based placeholder (label/icon) instead of a broken image
And images whose thumbnail failed to generate also fall back to a placeholder, not a broken image
```

## AC-4: Click selects an item
```gherkin
Given the grid is showing items
When the user clicks a thumbnail
Then that cell shows a visible selected state
And the selected item id is held in state (the seam Plan 03-02's inspector consumes)
And clicking another cell moves the selection
```

## AC-5: Local files served safely + library switch
```gherkin
Given the renderer is sandboxed (contextIsolation, no FS access)
When the grid requests imgman://thumb/<id> or imgman://original/<id>
Then the main process serves the file only from inside the ACTIVE library's images/<id>/ folder
And a request with an invalid id or a path-traversal attempt is rejected (no file outside the library is served)
And after switching libraries the grid shows the new library's items and thumbnails
```

<task type="auto">
  <name>Task 1: imgman:// protocol + items:list query/IPC</name>
  <files>src/main/protocol.ts, src/main/index.ts, src/main/services/items.ts, src/main/ipc/items.ts, src/main/ipc/index.ts</files>
  <action>
    Serve library files to the sandboxed renderer and expose the item list.
    - src/main/protocol.ts:
      • Export `IMGMAN_SCHEME = 'imgman'` and `registerImgmanScheme()` that calls `protocol.registerSchemesAsPrivileged([{ scheme, privileges: { standard: true, secure: true, supportFetchAPI: true, stream: true } }])`. This MUST be called before app `whenReady` (privileged schemes register at startup).
      • Export `registerImgmanProtocol()` (call after app ready) using `protocol.handle(IMGMAN_SCHEME, async (request) => …)`:
        - Parse the URL: host is the kind ('thumb' | 'original'), pathname is the item id.
        - Validate id with a strict UUID regex; reject anything else (return new Response(null,{status:400})). This blocks path traversal — ids never contain slashes/dots.
        - Resolve the active library via getActiveLibrary(); if none → 404.
        - thumb → `<imagesDir>/<id>/thumbnail.webp`. original → look up ext via getDb (`SELECT ext FROM items WHERE id=?`) then `<imagesDir>/<id>/original.<ext>` (or `original` when ext empty).
        - Confirm the resolved absolute path stays within imagesDir (defense-in-depth: resolve + startsWith check); if missing file → 404.
        - Return the file. Prefer `net.fetch(pathToFileURL(absPath).toString())` (Electron's net handles streaming + range), or read the file and return a Response with an appropriate Content-Type.
    - src/main/index.ts: call `registerImgmanScheme()` at top-level (module load, before whenReady); call `registerImgmanProtocol()` inside `app.whenReady().then(...)` before/after createWindow.
    - src/main/services/items.ts: add `listItems(): Item[]` → `SELECT id,name,ext,type,size_bytes,width,height,rating,created_at,imported_at FROM items ORDER BY imported_at DESC` (return [] when no DB open). Define+export the `Item` type matching those columns.
    - src/main/ipc/items.ts: `registerItemsIpc()` with `ipcMain.handle('items:list', () => listItems())`. Register it from src/main/ipc/index.ts. (Leave the existing items:count handler where it is.)
    Avoid: serving any path outside the active library; using the deprecated `protocol.registerFileProtocol` callback API (use `protocol.handle`); registering the privileged scheme after app ready (it silently won't be privileged).
  </action>
  <verify>`npm run typecheck` passes. In `npm run dev`, `window.api.items.list()` returns the imported rows; loading `imgman://thumb/<a-real-id>` shows the thumbnail; an invalid id returns an error not a file. (Full visual check at the checkpoint.)</verify>
  <done>AC-1 (data), AC-5 (safe local serving + switch) backend satisfied.</done>
</task>

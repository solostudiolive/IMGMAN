<objective>
## Goal
Add nested folders: a left-sidebar folder tree (create / rename / delete), assigning the
selected item to folders from the inspector, and filtering the grid to one folder's items.
Folders live in the existing `folders` / `item_folders` tables.

## Purpose
Folders are the second organizing primitive of the MVP ("folders (nested)") alongside tags
(04-02). They give the user a hierarchy to browse by, and are the first grid *filter* —
establishing the selected-scope → items-query path that 04-04 search will generalize.

## Output
- `folders` service (tree CRUD + assign/unassign + items-in-folder + folders-for-item) over
  `folders`/`item_folders`.
- `folders:*` IPC + a shared `Folder` type via preload/types.
- `FolderTree` sidebar (nested tree, "All items" root, create/rename/delete) wired into
  LibraryGate to filter the grid.
- `FolderAssigner` inspector section (chips of the item's folders + add/remove), mirroring
  the 04-02 TagEditor.
</objective>

<acceptance_criteria>

## AC-1: Create nested folders
```gherkin
Given a library is open
When the user creates a folder "Refs" at the root, then a folder "Logos" inside "Refs"
Then the sidebar shows "Logos" nested under "Refs"
And both persist (reopening the library still shows the tree)
```

## AC-2: Filter the grid by folder
```gherkin
Given items exist and a folder has some items assigned
When the user clicks that folder in the sidebar
Then the grid shows only the items assigned to that folder
And clicking "All items" restores the full library view
```

## AC-3: Assign and remove an item from a folder
```gherkin
Given an item is selected in the inspector
When the user assigns it to "Logos" via the inspector folder control
Then a "Logos" chip appears on the item and the link persists in item_folders
And the item appears when "Logos" is the active filter
And removing the chip unassigns it (the item and the folder both remain)
```

## AC-4: Rename and delete folders
```gherkin
Given a folder "Refs" with a child "Logos" exists
When the user renames "Refs" to "References"
Then the sidebar label updates and persists
And when the user deletes "References"
Then "References" and its descendant "Logos" disappear from the tree
And the items themselves remain in the library (visible under "All items")
```

## AC-5: folders IPC is validated and safe
```gherkin
Given the renderer calls a folders:* channel
When the folder name is empty/whitespace-only
Then create/rename is a no-op (no blank folder)
And assigning an item already in the folder is a no-op (no duplicate link)
And when no library is open or an id is unknown
Then calls return an empty list / no-op without throwing across IPC
```

      - `renameFolder(id, name): Folder[]` — trim; if empty, no-op. UPDATE folders SET name=?
        WHERE id=?. Return listFolders().
      - `deleteFolder(id): Folder[]` — in a transaction, collect id + all descendants (walk
        parent_id; bound depth/iterate over the flat list — no recursive CTE needed), then
        DELETE their item_folders links and the folders rows. Items are NOT deleted. Return
        listFolders().
      - `listItemsInFolder(folderId): Item[]` — items DIRECTLY linked to folderId, using the
        SAME projection/ORDER BY as items.listItems (import the Item type from services/items;
        JOIN item_folders → items, ORDER BY imported_at DESC).
      - `listFoldersForItem(itemId): Folder[]` — folders linked to itemId, ordered by name.
      - `assignItemToFolder(itemId, folderId): Folder[]` — INSERT OR IGNORE into
        item_folders(item_id, folder_id) (idempotent). Return listFoldersForItem(itemId).
      - `removeItemFromFolder(itemId, folderId): Folder[]` — DELETE FROM item_folders WHERE
        item_id=? AND folder_id=?. Return listFoldersForItem(itemId).
    Create `src/main/ipc/folders.ts` with `registerFoldersIpc()` registering channels:
      `folders:list`→listFolders; `folders:create`→(name,parentId) createFolder;
      `folders:rename`→(id,name) renameFolder; `folders:delete`→(id) deleteFolder;
      `folders:itemsIn`→(folderId) listItemsInFolder; `folders:forItem`→(itemId)
      listFoldersForItem; `folders:assign`→(itemId,folderId) assignItemToFolder;
      `folders:unassign`→(itemId,folderId) removeItemFromFolder.
    Call `registerFoldersIpc()` from `src/main/ipc/index.ts` (add BOTH the import AND the call —
    verify the call lands, not just the import).
    Extend preload `window.api` with a `folders` namespace and add `Folder` + the `folders` block
    to `IpcApi` in `src/preload/types.ts` (itemsIn returns `Item[]`).
    Avoid: interpolating values into SQL (bind params); deleting items on folder delete;
    creating blank folders; throwing across IPC for unknown ids (return []/no-op); a recursive
    SQL CTE (build the descendant set in JS from the flat list).
  </action>

<objective>
## Goal
Float audio/video hover previews in a **popover anchored to the top-right of the grid viewport** instead of replacing the cell thumbnail inline. The popover appears on hover-intent (180 ms) with the playing media, stays with the mouse as it tracks across cells, and dismisses cleanly when the cursor leaves both the popover and its triggering cell.

## Purpose
The current inline hover-preview (Phase 6, Plan 06-04) replaces the thumbnail inside the cell — it works, but it pushes the grid layout, the media is tiny (cell-sized), and fast mouse sweeps trigger flicker. A floating popover decouples the preview surface from the tile: the thumbnail stays put, the media renders at a usable size in a stable top-right corner, and only one popover lives at a time (the single most-recent cell wins). This matches the "always-visible corner preview" interaction pattern from Eagle-class asset managers while staying scoped to audio/video (PDF and image-GIF hover remain inline — GIF animate-in-cell is cheap; PDFs already have their own inline viewer).

## Output
- `Grid.tsx`: replace inline `preview` state with a single shared popover context (hover-intent timer + active item + popover position). Move `<video>`/`<audio>` render out of `Cell` into a floating `HoverPreview` popover. `onMouseEnter`/`onMouseLeave` on cells update the shared state instead of each cell owning its own.
- `Grid.css`: add `.hover-preview` rules (position: fixed, top-right anchor, Eagle token styling, entrance fade + scale).
</objective>

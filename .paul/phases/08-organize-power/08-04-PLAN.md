<objective>
## Goal
Add **find duplicates**: detect byte-identical files via a content hash (SHA-256 of the original
bytes), then surface duplicate groups in a modal where the user can keep one and delete the rest —
reusing the Phase-7 `items:delete` batch op. This is the FINAL Phase-8 slice; completing it triggers
the phase transition.

## Purpose
A core Eagle-parity housekeeping feature. Content hashing is exact-match (catches re-imported / copied
files regardless of name), stored once per item in a new `items.content_hash` column. Computed at
import (piggybacking the existing pipeline, like 08-02's palette) and backfilled for existing items via
a maintenance scan (mirroring `backfillPalettes`). Grouping is a cheap GROUP BY over the stored hashes.

## Output
- New `items.content_hash` column (schema.sql for fresh DBs + an idempotent `ALTER TABLE` migration in
  `db/index.ts` for existing libraries; `user_version` bumped to 2).
- `services/hash.ts`: `hashFile(absPath)` (streamed SHA-256 → hex) + `hashBuffer(buf)`.
- Import computes + stores `content_hash` (file path → `hashFile`; clipboard buffer → `hashBuffer`);
  failure leaves it NULL, never aborts import.
- `backfillHashes()` (all item types, `content_hash IS NULL`) + `findDuplicateGroups()` services, exposed
  as `items:backfillHashes` / `items:findDuplicates` IPC.
- `DuplicatesModal`: lists each duplicate group with thumbnails, pre-selects all-but-newest for deletion,
  shows reclaimable bytes, deletes selected via the existing `items:delete`. Launched from Settings →
  Library maintenance (next to "Extract colors").
</objective>

## Patterns to follow
- MIRROR 08-02 for hashing: compute inside the SAME import flow (failure → NULL, never abort), store to
  BOTH the items row and metadata.json; a `backfillHashes()` over `content_hash IS NULL` rows triggered
  from Settings maintenance. Difference: hashing covers ALL item types (not just images).
- Hash the ORIGINAL bytes (images/<id>/original.<ext>), streamed (createReadStream → crypto SHA-256) so
  large files don't load fully into memory. Clipboard import hashes the buffer directly.
- Schema migration: schema.sql gets the column for fresh DBs; existing DBs get an idempotent
  `ALTER TABLE items ADD COLUMN content_hash TEXT` guarded by a `pragma table_info(items)` check (the
  schema's `CREATE ... IF NOT EXISTS` cannot add a column). Bump `SCHEMA_VERSION`/`user_version` to 2.
- REUSE `items:delete` (07-05) for removal; the modal only SELECTS ids to delete — no new delete logic.
- Token-styled modal mirroring SettingsModal/BatchTagDialog (backdrop + panel, self-owns Escape,
  stopPropagation past the global key handler). Thumbnails via the existing `imgman://thumb/<id>`.

## Anti-regression
- `content_hash` is additive: import, list, get, search, delete all behave as before when it's unused.
- The migration must be idempotent and not disturb existing rows/data (ALTER ADD COLUMN defaults NULL).
- No new dependency (Node's built-in `crypto` + `fs` streams). No CSP change.

<acceptance_criteria>

## AC-1: Content hash stored at import + backfilled
```gherkin
Given a new file is imported (path or clipboard)
Then its items.content_hash is the lowercase hex SHA-256 of the original bytes (NULL only if hashing failed)
And metadata.json carries the same content_hash

Given an existing library with rows that predate hashing (content_hash IS NULL)
When "Find duplicates" runs the backfill
Then every readable item gets a content_hash (idempotent; only NULL rows are touched; all item types, not just images)
And items whose original file is missing/unreadable are skipped (left NULL), not fatal
```

## AC-2: Duplicate grouping
```gherkin
Given items with content_hash populated
When findDuplicateGroups() runs
Then it returns groups of 2+ items sharing the same non-NULL content_hash
And each group lists its items (grid projection) with a stable order (e.g. imported_at ASC so the oldest is first)
And items with a unique or NULL hash are not returned
```

## AC-3: Duplicates modal — review + delete
```gherkin
Given duplicate groups exist
When the user opens Settings → "Find duplicates"
Then a modal lists each group (thumbnails + name + size), with all-but-one item pre-checked per group
  (default keep the newest, delete the rest) and a summary of reclaimable files/bytes
When the user adjusts the checkboxes and clicks "Delete selected"
Then those items are removed via items:delete, the grid reloads, and the modal reflects the new state
  (group disappears when it drops below 2 members)
And a group with everything unchecked deletes nothing
```

## AC-4: No regressions
```gherkin
When `npm run typecheck` (node + web) and `npm run build` run
Then both pass with no new errors
And the content_hash migration is idempotent across repeated app launches (re-running adds nothing)
And import / list / get / search / existing delete all still work; no new dependency; CSP unchanged
```

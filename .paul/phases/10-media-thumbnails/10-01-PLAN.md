<objective>
## Goal
Generate real thumbnail images for video, audio, PDF, and font files during import — replacing the current generic TypeIcon placeholders in the grid/inspector.

## Purpose
The v1.0 PROJECT.md explicitly defers: "No real thumbnails for video/audio/pdf/font — grid uses type-based placeholder icons until V1 media thumbnails." This phase delivers that V1 capability, making non-image assets browseable at a glance in the grid view.

## Decision: Pure-JS approach (option-b)
Selected **option-b (pure-JS libraries)** to avoid native ffmpeg binary packaging issues that v1.0 explicitly deferred (`asarUnpack` for native modules is an unresolved carry-forward in STATE.md line 75). Keeps the phase dependency-free at the binary level:
- **Video:** `ffmpeg.wasm` — extract a frame at 25% duration via `fetchFile` + `ffmpeg.ffprobe` for duration, then `ffmpeg.screenshot` to PNG → sharp → webp
- **Audio:** `ffmpeg.wasm` — extract embedded cover art or render waveform from first audio stream
- **PDF:** `pdfjs-dist` — render first page at 200px width → sharp → webp
- **Font:** `opentype.js` — render "Aa" sample text via SVG path → sharp → webp

New npm deps: `ffmpeg.wasm`, `pdfjs-dist`, `opentype.js`. All self-contained JS, CSP-safe, no native binaries. sharp (already a dependency) is reused for PNG/SVG→webp conversion. Performance is acceptable for v1.1; if import of 10k+ media files is slow, Phase 12's worker-pool refactor addresses it.
</objective>

```gherkin

When importFile processes it
Then a thumbnail.webp is generated by rendering a waveform image or cover-art extract

And the grid shows a real thumbnail instead of a TypeIcon placeholder
```

## AC-3: PDF thumbnails generated on import
```gherkin
Given a PDF file being imported
When importFile processes it
```

```gherkin
Given a font file (.ttf/.otf/.woff/.woff2) being imported

```

  <name>Create mediaThumbnail service module</name>
  <files>src/main/services/mediaThumbnail.ts</files>
  <action>
    Create `src/main/services/mediaThumbnail.ts` with extraction functions:

    - `extractVideoThumbnail(inputPath, outputPath): Promise<ItemMediaMeta | null>` — uses ffmpeg.wasm to probe duration via `ffmpeg.ffprobe()`, extract a frame at 25% via `ffmpeg.screenshot()`, convert PNG→webp via sharp
    - `extractAudioThumbnail(inputPath, outputPath): Promise<ItemMediaMeta | null>` — uses ffmpeg.wasm to extract embedded cover art or render a waveform; probe duration
    - `extractPdfThumbnail(inputPath, outputPath): Promise<ItemMediaMeta | null>` — uses pdfjs-dist to render first page at 200px width, convert to webp via sharp
    - `extractFontThumbnail(inputPath, outputPath): Promise<ItemMediaMeta | null>` — uses opentype.js to render "Aa" sample via SVG path, convert to webp via sharp
    - `extractMediaThumbnail(type: ItemType, inputPath, outputPath): Promise<ItemMediaMeta | null>` — dispatcher, imports `ItemType` from `./import` (matches items.ts line 9 pattern)
    - `ItemMediaMeta` interface: `{ width: number|null, height: number|null, durationMs: number|null }`

    All functions return `null` on any error (never throw) — mirrors palette.ts defensive pattern (lines 18–54). sharp handles PNG/SVG→webp. ffmpeg.wasm loaded once via lazy singleton to avoid repeated `ffmpeg.load()` across imports.

    pdfjs-dist in Node main process: use `pdfjsLib.GlobalWorkerOptions.workerSrc = null; pdfjsLib.GlobalWorkerOptions.workerSrc = '...'` or the `pdfjs-dist/legacy.js` build for Node without worker. Render page to a canvas-like object — pdfjs-dist supports `getDocument(pathOrData)` with `{data: Uint8Array}` and `page.render({canvasContext})` where canvasContext is a minimal stub that captures ImageData, then sharp converts the raw RGBA buffer.

    opentype.js: `font.draw(ctx, "Aa", 0, 0, fontSize)` requires a canvas 2D context. Since we're in main process, use a minimal SVG approach — opentype.js has `font.toPath()` or `font.getPaths()` that returns SVG path strings, then sharp can rasterize SVG → webp directly.

    ffmpeg.wasm: requires loading the WASM core on first use. Use lazy initialization — `let ffmpegInstance: FFmpeg | null = null; async function getFFmpeg(): Promise<FFmpeg>` — load once, reuse across all imports.
  </action>

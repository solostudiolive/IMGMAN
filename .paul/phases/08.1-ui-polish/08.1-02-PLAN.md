<objective>
## Goal
Deliver the visible "Refined dark, Eagle-like" restyle: a refreshed dark+light **color/contrast token
palette** (layered grey surfaces, hairline borders, crisper accent, soft elevation shadows, larger
radii) plus **density/layout polish** on the real surfaces — grid/list cards, sidebar rows, search
toolbar, inspector, and menus/dialogs. This is the slice that actually makes the app look modern.

## Purpose
8.1-01 only swapped the typeface (foundation). This slice changes what the user sees. Because almost
every component references semantic tokens (or `var(--color-*)` inline), refreshing tokens.css
propagates app-wide for free; the remaining work is targeted component polish where visuals are
hard-coded in CSS or inline (grid cells).

## Output
- Refreshed tokens.css: deeper layered greys (app/panel/content/elevated with clearer separation),
  hairline borders, refined hover/selected, a crisper accent, softer/larger elevation shadows, and
  larger radii (md/lg). Dark is primary; light kept coherent.
- base.css: an accent `:focus-visible` ring for inputs/buttons (modern affordance).
- Targeted polish: grid/masonry **cells** (Grid.tsx inline) and list rows (Grid.css) get card radius +
  refined selection ring/hover lift; AppShell panel seams, SearchBar field, ContextMenu + SettingsModal
  elevation, and ContentToolbar spacing refined — all via tokens.
</objective>

## Patterns to follow
- TOKEN-LED: make the palette/elevation/radius changes in tokens.css first — most surfaces update for
  free. Only edit a component file where the visual is hard-coded (Grid.tsx inline cells) or needs a
  new rule (focus ring, hover-lift).
- Keep the Phase-5 token CONTRACT: same token names (components depend on them); change values, and ADD
  tokens only if needed (e.g. --shadow-3, --ring). Never reintroduce raw hex in components.
- Dark is the primary visual target; keep light theme coherent (adjust its values too, don't break it).
- No behavior/layout-structure changes — restyle only. No new dependency. Respect the existing CSP
  (no external assets).

## Anti-regression
- Selection/hover must stay clearly distinguishable in BOTH themes (don't wash out --color-surface-selected).
- 60fps grid scroll: prefer cheap properties; keep cell hover effects to transform/opacity/box-shadow
  (avoid layout-thrashing properties); no per-cell heavy filters.

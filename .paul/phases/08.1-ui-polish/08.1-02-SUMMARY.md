## Decisions Made

| Decision | Rationale | Impact |
|----------|-----------|--------|
| Eagle "flat near-black" dark (near-uniform panes) | Match the actual Eagle look during human-verify, not the plan's layered-grey suggestion | bg-app/panel #1a1a1a, content #1d1d1d, elevated #2a2a2a (inputs/fields only) |

**Total impact:** Restyle stayed in scope (no behavior/dep/schema change). The dark palette, selection color, and radii diverged from the plan's *suggested values* toward Eagle's actual aesthetic during the visual checkpoint — the plan explicitly framed those values as tunable suggestions, so this is expected human-verify iteration, not scope creep.

### Reinterpretations (vs plan suggestions)

1. **Dark palette — flat near-black, not layered greys.** Plan suggested a stepped grey ramp (bg-app ~#161618 → elevated ~#26262a). Actual: near-uniform #1a1a1a panes with #1d1d1d content and #2a2a2a elevated reserved for inputs — matches Eagle's flat dark surface.
2. **Selection color.** Plan suggested accent-tinted selection everywhere; actual reserves blue for grid tiles and uses neutral-grey selection in sidebar/list (Eagle behavior).
3. **Radii.** Plan suggested md=8/lg=12; actual md=6/lg=10 (restrained). `--shadow-3` and `--ring` added as planned.

### Files-modified deviation

- `src/renderer/src/components/AppShell.css` was listed in the plan's `files_modified` but was **not** edited — token propagation already restyled the shell seams, so no direct edit was required.

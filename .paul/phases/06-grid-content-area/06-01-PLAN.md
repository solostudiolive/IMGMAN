<objective>
## Goal
Add the **content-area view toolbar** that sits above the grid: a **thumbnail-size slider**
and a **sort control** (field + direction). Wire both into a persisted view-state hook so the
existing uniform grid honors size and sort. This is the foundation the later Phase 6 plans
(masonry, list view, hover preview) plug into.

## Purpose
Phase 6 turns the functional v0.1 grid into an Eagle-class content area. Eagle's signature is
the top-of-content view bar (size slider + sort + view modes). This plan ships the bar plus the
two cheapest, highest-value controls (size + sort) and establishes the `useGridView` state model
+ `ContentToolbar` shell that 06-02 (masonry / view-mode switch) and 06-03 (list) extend — so
those plans add a mode, not a toolbar.

## Output
- `useGridView` hook: persisted `{ thumbSize, sortField, sortDir }` + setters (localStorage).
- `ContentToolbar` component (+ CSS): size slider + sort field `<select>` + asc/desc toggle.
- `Grid` accepts a `thumbSize` prop and sizes its responsive columns from it.
- `LibraryGate` renders the toolbar above the grid and sorts the loaded items (renderer-side)
  before handing them to `Grid`.
</objective>

    - State shape: `{ thumbSize: number; sortField: SortField; sortDir: 'asc' | 'desc' }`
      where `type SortField = 'imported' | 'created' | 'name' | 'rating' | 'size'`.
    - Defaults: thumbSize 140, sortField 'imported', sortDir 'desc' (matches today's
      `ORDER BY imported_at DESC` so behavior is unchanged until the user touches the control).
    - Persist each field to localStorage under keys `imgman.gridview.thumbSize`,
      `imgman.gridview.sortField`, `imgman.gridview.sortDir`. Mirror AppShell's read/write
      helpers: try/catch reads with validated fallbacks (clamp thumbSize to [96, 280];
      validate sortField against the allowed set and sortDir against 'asc'|'desc'); best-effort
      writes. Export `SortField` and a `THUMB_MIN`/`THUMB_MAX` constant pair (96/280).
    - Return `{ thumbSize, sortField, sortDir, setThumbSize, setSortField, setSortDir }`.
    - Also export a `compareItems(a, b, field, dir): number` pure helper used by LibraryGate:
      name → localeCompare (sensitivity 'base', numeric: true); rating/size/created/imported →
      numeric on rating / size_bytes / created_at / imported_at; stable tiebreak on `id`.
      `dir === 'desc'` negates the result.

    Create `ContentToolbar` (src/renderer/src/components/ContentToolbar.tsx), presentational/controlled:
      Props: `{ thumbSize, sortField, sortDir, onThumbSize, onSortField, onSortDir, count }`.
    - Left: a sort `<label>Sort</label>` + `<select>` with options Imported / Date created /
      Name / Rating / Size (values matching SortField), and a direction toggle button showing
      ↑ (asc) / ↓ (desc) that calls onSortDir(dir === 'asc' ? 'desc' : 'asc'); aria-label
      "Sort direction".
    - Right: a `<input type="range" min={THUMB_MIN} max={THUMB_MAX}>` bound to thumbSize
      (onChange → onThumbSize(Number(value))) with a small "size" glyph/label; aria-label
      "Thumbnail size". Optionally show `{count} items` as a muted caption between the two groups.
    - All structure/spacing/hover in ContentToolbar.css (token-based; a single `.content-toolbar`
      flex row, controls styled to match SearchBar.css selects/buttons). Keep the row compact
      (height ~36px, var(--space-*) padding, bottom border var(--color-border)).
    Avoid: storing any state inside ContentToolbar (LibraryGate owns it via the hook); touching
    AppShell or the shell top toolbar; adding dependencies.
  </action>

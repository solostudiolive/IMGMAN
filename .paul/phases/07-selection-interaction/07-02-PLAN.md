<objective>
## Goal
Add **keyboard navigation** to the content grid: arrow keys move the active (primary) item and
select it; Shift+arrows extend the selection; Ctrl/Cmd+A selects all; Home/End jump to first/last;
Enter toggles the quick preview. The active item scrolls into view. Navigation is 2D in grid mode
(Left/Right ±1, Up/Down ±columns) and 1D in list/masonry.

## Purpose
Keyboard navigation is core to "feels like a real desktop app" and retires the long-standing
"no arrow-key navigation" concern. It drives the same `useSelection` model from 07-01, so no new
selection machinery is needed — only key handling + scroll-into-view plumbing.

## Output
- `Grid` exposes an imperative handle (`scrollToId`) and reports its current column count upward
  (computed from container width + thumbSize; 1 in list mode), via a measured wrapper.
- `LibraryGate` handles the navigation keys against the current `orderedIds` + columns, updates the
  selection via `useSelection`, and scrolls the new active item into view.
</objective>

## AC-1: Arrow keys move + select the active item
```gherkin
Given items are shown and one is active (or none yet)
When the user presses an arrow key (no modifier)
Then in grid mode Left/Right move by one and Up/Down move by one row (columns), selecting only the new item
And in list/masonry mode Up/Down (and Left/Right) move by one in order
And if nothing was active, the first item becomes active
And movement clamps at the ends (no wrap, no out-of-range)
```

## AC-2: Shift+arrows extend; Ctrl/Cmd+A; Home/End; Enter
```gherkin
Given an active item
When the user presses Shift+arrow
Then the selection extends from the anchor to the new active item (range), as with shift-click
When the user presses Ctrl/Cmd+A
Then all items in the current scope are selected
When the user presses Home / End
Then the first / last item becomes the active single selection
When the user presses Enter
Then the quick preview of the active item toggles (like Space)
```

## AC-3: Active item scrolls into view
```gherkin
Given navigation moves the active item outside the visible area (grid or list)
When the move happens
Then the grid/list scrolls so the active item is visible
(Masonry: navigation still selects correctly; auto-scroll is best-effort.)
```

```gherkin
Given focus is in a text input / textarea / contenteditable, or the Settings modal is open
When navigation keys are pressed
Then the grid does NOT navigate (existing input/modal guards apply)
And arrow keys still work normally inside those inputs
```

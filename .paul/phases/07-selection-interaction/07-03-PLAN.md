<objective>
## Goal
Add **rubber-band (marquee) selection**: dragging on an empty area of the grid draws a selection
rectangle and selects every item whose cell it intersects. Holding Shift/Ctrl while dragging adds
to the existing selection; a plain background click (no drag) clears the selection.

## Purpose
Marquee is the third selection gesture (after click/keyboard) that makes the grid feel like a real
desktop app — the "rubber-band" item in the Phase-7 goal. It reuses `useSelection` (one new method)
and the existing grid surface.

## Output
- `useSelection.applyMarquee(ids, additive)` — replace-or-add a batch of ids.
- Each cell (grid/masonry/list) carries `data-item-id` for hit-testing.
- `Grid` owns background pointer interaction: drag → marquee rectangle + intersect mounted cells →
  `onMarqueeSelect`; plain background click → `onBackgroundClick`. A token-styled marquee overlay.
- `LibraryGate` wires `onMarqueeSelect → applyMarquee` and `onBackgroundClick → clear` (this absorbs
  the 07-01 empty-click-clear into the same Grid interaction, avoiding click/drag conflicts).
</objective>

## Patterns to follow
- Renderer-only; no IPC/main/SQL change. Tokens for the marquee rectangle (Grid.css).
- Hit-test via `wrapRef`'s DOM: `querySelectorAll('[data-item-id]')`, intersect each
  getBoundingClientRect() with the drag rect in CLIENT coords; the visual overlay is positioned
  relative to the wrapper (subtract the wrapper's rect).
- Virtualization caveat (document, don't fight): only MOUNTED cells can be hit-tested, and there is
  NO auto-scroll during drag this plan — marquee selects what's currently rendered in the viewport.

    Grid.tsx (props): add
      `onMarqueeSelect?: (ids: string[], additive: boolean) => void` and
      `onBackgroundClick?: () => void`.
    On the wrapper div (`wrapRef`, set `position: relative`):
    - `onMouseDown`: only when `e.button === 0` AND the target is NOT inside a `[data-item-id]`
      element (i.e. empty space). Record start `{x,y}` (clientX/clientY) and `additive = e.shiftKey
      || e.ctrlKey || e.metaKey`. Attach `mousemove`/`mouseup` listeners on `document`.
    - `mousemove`: compute the drag rect from start→current (client coords). Once movement exceeds a
      ~4px threshold, mark `dragging` and render the overlay. On each move, hit-test:
      `wrapRef.current.querySelectorAll('[data-item-id]')`, for each compute getBoundingClientRect()
      and test intersection with the drag rect; collect `data-item-id` values; call
      `onMarqueeSelect(ids, additive)` (live update so the selection follows the drag).
    - `mouseup`: remove listeners. If it never crossed the threshold (a plain click on empty space),
      call `onBackgroundClick()`. Clear the overlay + dragging state.
    - Render a marquee overlay `<div className="marquee">` positioned with left/top/width/height in
      WRAPPER-relative coords (subtract `wrapRef.getBoundingClientRect()`), `pointerEvents: 'none'`,
      only while dragging.

      (left-press on empty space only; wheel/scrollbar untouched).

      border-radius:2px; }` (token-based; if color-mix feels risky, use var(--color-surface-selected)

        `onBackgroundClick={() => sel.clear()}`.
    - Leave keyboard nav, mouse click selection, and everything else unchanged.
    Avoid: auto-scroll during drag (deferred — note in SUMMARY), selecting off-screen/unmounted
    cells, any IPC/main change.

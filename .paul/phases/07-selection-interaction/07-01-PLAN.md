<objective>
## Goal
Introduce a **multi-select model** for the content grid: plain click selects one item; Ctrl/Cmd-click
toggles an item; Shift-click selects a contiguous range from the anchor. A "primary" (last-clicked)
item continues to drive the inspector and quick preview. Works identically in grid, masonry, and list.

## Purpose
Selection is the foundation for the rest of Phase 7 — context menus, batch operations, and the
multi-item inspector all act on a selection set. This plan replaces the single `selectedId` with a
selection set + primary/anchor while keeping current single-item behaviour (inspector, Space preview)
intact, so later plans have a selection to build on.

## Output
- `useSelection` hook: `{ selected: Set<string>, primary, anchor }` + `handleSelect(id, mods)`,
  `selectAll()`, `clear()`, driven by the current ordered (sorted) id list for range selection.
- `Grid` cells (grid/masonry/list) report click modifiers and highlight every selected item.
- `LibraryGate` owns the hook; inspector + quick preview use `primary`; selection resets on scope change.
- `ContentToolbar` count shows "N selected" when a multi-selection is active.
</objective>

<acceptance_criteria>

## AC-1: Click selects one; Ctrl/Cmd-click toggles
```gherkin
Given items are shown (any view mode)
When the user plain-clicks an item
Then only that item is selected (any previous selection is replaced) and it becomes the primary
When the user Ctrl-clicks (or Cmd-clicks on macOS) an item
Then that item's selected state toggles without clearing the rest, and it becomes the primary
```

## AC-2: Shift-click selects a range
```gherkin
Given an anchor item is selected
When the user Shift-clicks another item
Then every item between the anchor and the clicked item (in the current sort order) becomes selected
And the clicked item becomes the primary (the anchor stays put for further shift-clicks)
```

## AC-3: Primary drives inspector + quick preview; multi-select styling
```gherkin
Given a multi-selection is active
Then all selected items show the selected highlight in grid/masonry/list
And the inspector shows the primary (last-clicked) item
And pressing Space opens the quick preview of the primary item (as before)
And the toolbar shows "N selected" while more than one item is selected
```

## AC-4: Selection resets sensibly
```gherkin
When the active library, folder scope, or search changes
Then the selection is cleared
And when a selected item disappears from the filtered list, it's removed from the selection
And clicking empty space / pressing Escape (when no preview is open) clears the selection
```

## AC-5: No regressions
```gherkin
When `npm run typecheck` and `npm run build` run
Then both pass with no new errors
And grid/masonry/list rendering, sort, size, hover preview, folder/search/import, and the
     single-item inspector edits all behave as before for a single selection
And no main/preload/IPC/SQL files were modified
```

<task type="auto">
  <name>Task 1: useSelection hook</name>
  <files>src/renderer/src/hooks/useSelection.ts</files>
  <action>
    Create `useSelection()` returning:
    - state: `selected: Set<string>`, `primary: string | null`, `anchor: string | null`.
    - `handleSelect(id: string, orderedIds: string[], mods: { ctrl: boolean; shift: boolean }): void`
      computing the next selection:
        • shift && anchor present: select the contiguous range in `orderedIds` from anchor→id
          (inclusive); set primary = id; KEEP anchor. (If anchor missing, treat as plain click.)
        • ctrl (Ctrl or Cmd): toggle id in a copy of `selected`; set primary = id; set anchor = id.
        • plain: selected = new Set([id]); primary = id; anchor = id.
    - `selectAll(orderedIds: string[])`: selected = new Set(orderedIds); primary/anchor = last id.
    - `clear()`: empty set; primary = null; anchor = null.
    - `prune(presentIds: string[])`: drop any selected id not in presentIds; if primary/anchor were
      dropped, set them to null (used when the filtered list changes).
    Use `useState` + `useCallback`. Keep it pure renderer state (no persistence). Export a
    `SelectMods = { ctrl: boolean; shift: boolean }` type for the Grid props.
    Avoid: storing the ordered list in the hook (pass it per call so it always reflects current sort);
    any IPC.
  </action>
  <verify>npm run typecheck:web passes; unit-reasoning: plain/ctrl/shift produce the expected sets; prune drops absent ids; selectAll/clear behave.</verify>
  <done>Selection state machine ready for AC-1/AC-2/AC-4.</done>
</task>

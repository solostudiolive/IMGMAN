<objective>
## Goal
Add **right-click context menus** across the three interaction surfaces — grid/masonry/list
**items**, sidebar **folders**, and inspector **tag chips** — built on one reusable, token-styled
`ContextMenu` primitive (cursor-positioned, viewport-flipping, dismiss on Escape / outside-click /
scroll). Item-menu actions operate on the single right-clicked item using EXISTING single-item IPC.

## Purpose
Context menus are the "feels like a real desktop app" layer of the Phase-7 goal. This plan delivers
the menu infrastructure + the three menu surfaces wired to operations that already exist
(`items:update`, `folders:assign/create/rename/delete`, `tags:remove`). True multi-item batch and
`items:delete` are deliberately left to 07-05; this keeps 07-04 renderer-only.

## Output
- `components/ContextMenu.tsx` + `ContextMenu.css` — a reusable menu primitive: action / submenu
  (one level) / separator nodes, positioned at a viewport point, flips to stay on screen, and
  dismisses on Escape, outside mousedown, scroll, resize, blur, or after an action runs.
- Grid reports a cell right-click via a new `onItemContextMenu(id, x, y)` prop (grid/masonry Cell +
  ListRow), suppressing the native menu.
- LibraryGate hosts the **item** menu: Quick preview · Rating ▸ (0–5) · Add to folder ▸ (folder list).
- FolderTree adds a **folder** menu (New subfolder · Rename · Delete) reusing its existing handlers.
- TagEditor adds a **tag-chip** menu (Remove from item).
</objective>

  <name>Task 1: Reusable ContextMenu primitive + token styles</name>
  <files>src/renderer/src/components/ContextMenu.tsx, src/renderer/src/components/ContextMenu.css</files>
  <action>
    Create a presentational `ContextMenu` rendered through `createPortal(…, document.body)` so it
    escapes pane overflow/clipping.

    Node model (exported):
      export type MenuNode =
        | { kind: 'action'; label: string; icon?: string; danger?: boolean; disabled?: boolean; onSelect: () => void }
        | { kind: 'submenu'; label: string; icon?: string; items: MenuNode[] }
        | { kind: 'separator' }

    Props: `{ x: number; y: number; items: MenuNode[]; onClose: () => void }`.

    Behaviour:
    - Render a `position: fixed` menu (className "context-menu") at (x, y) — these are viewport
      coords (clientX/clientY), which is what position:fixed uses.
    - Viewport flip: after mount, measure the menu rect (ref + useLayoutEffect); if x+width >
      window.innerWidth, shift left by the overflow; if y+height > innerHeight, shift up. Keep within
      a small margin (e.g. 4px).
    - Dismiss: attach (on mount, in a useEffect) listeners that call onClose() on — document
      `mousedown` outside the menu root, `keydown` Escape (also stopPropagation + preventDefault so it
      doesn't reach the global LibraryGate handler), window `scroll` (capture), `resize`, and `blur`.
      Clean all up on unmount.
    - Action rows: button per 'action' node; on click → run node.onSelect() then onClose(). Disabled
      rows are non-interactive (aria-disabled, muted). 'separator' → a thin rule. 'danger' → red text.
    - Submenu (ONE level only): a row showing label + a ▸ affordance; on mouseenter (and focus) open a
      nested flyout menu (reuse this same component) positioned to the row's right, flipping to the
      left when it would overflow. Closing the parent closes children.
    ContextMenu.css: token-driven — `.context-menu` { position:fixed; z-index:1000;
      min-width:180px; padding:4px; background:var(--color-bg-elevated);
      border:1px solid var(--color-border); border-radius:var(--radius-md, 8px);
      box-shadow:var(--shadow-lg, 0 8px 24px rgba(0,0,0,.3)); font-size:var(--fs-sm,13px);
      color:var(--color-text); }; row hover → background:var(--color-surface-hover); disabled →
      color:var(--color-text-faint); separator → 1px var(--color-border) margin 4px 0; danger row →
      color:var(--color-danger). No raw hex except an opaque shadow fallback.

    Avoid: depending on any selection/IPC logic here (keep it presentational); multi-level nesting
    (one submenu level is enough); adding a portal library (use react-dom createPortal).
  </action>
  <verify>npm run typecheck:web passes; ContextMenu mounts via portal at (x,y), flips near edges, and closes on Escape / outside-click / scroll; submenu opens a single-level flyout.</verify>
  <done>AC-3 menu mechanics (positioning + dismissal) ready; reusable by Tasks 2–3.</done>
</task>

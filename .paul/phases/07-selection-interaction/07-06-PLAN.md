<objective>
## Goal
Add **batch rename** over the selection with a live-preview dialog supporting two modes: a **pattern**
(tokens `{name}` · `{ext}` · `{n}` with a start number + zero-padding) and **find & replace** (literal
or regex, case-sensitive toggle). New names are computed renderer-side with an instant old→new preview,
then persisted in one atomic transaction via a new `items:renameMany` channel.

## Purpose
Rename is the last batch action in the Phase-7 goal. It writes ONLY the `items.name` metadata column
(the on-disk file stays `images/<id>/original.<ext>` — safe, reversible by re-renaming). Reuses the
07-05 atomic batch-IPC pattern and the 07-04 item context menu.

## Output
- New service `renameItems(renames: {id, name}[]): number` — one transaction of
  `UPDATE items SET name = ? WHERE id = ?` (trimmed, non-empty only), returning rows changed.
- New IPC `items:renameMany` (+ preload + `IpcApi`).
- `renameItems.ts` — a pure renderer helper computing the new name for an item under a `RenameSpec`
  (pattern or find/replace), with safe invalid-regex handling.
- `BatchRenameDialog` — a token-styled modal: mode toggle, inputs, a live old→new preview list, Apply.
- LibraryGate: a "Rename…" entry in the item context menu (single + multi) opening the dialog over
  the selection in display order; Apply → `items:renameMany` → reload.
</objective>

## Patterns to follow
- Backend: one `db.transaction(...)` returning a count (mirror 07-05). Rename writes ONLY `items.name`;
  never touch ext, files, or `images/<id>`. `items_fts` is unwired → ignore (consistent with delete).
- New channel (NOT items:update / ItemPatch): `items:renameMany(renames)` where renames is
  `{ id: string; name: string }[]`.
- Compute new names in the RENDERER (instant preview); send only the final {id,name}[] to main.
  Skip entries whose computed name is blank (and the service also guards trimmed-empty).
- Modal keyboard-ownership (05-04 / BatchTagDialog): the dialog owns Escape + stops it reaching the
  global handler; LibraryGate guards its global keydown while the dialog is open (like `tagDialog`).

## AC-1: Pattern rename
```gherkin
Given several items are selected
When the user opens "Rename…", picks Pattern mode, and enters e.g. "Trip {n}" with Start=1, Pad=2
Then the preview shows each item's old name → new name ("Trip 01", "Trip 02", … in display order)

When the user clicks Apply
```

## AC-2: Find & replace (literal + regex)
```gherkin
Given several selected items whose names share a substring
When the user picks Find & Replace, enters find/replace text, and toggles case-sensitive

When the user enables "Use regex" and types an INVALID pattern
Then an inline error shows and Apply is disabled (no crash); fixing it re-enables Apply
When the user enters a VALID regex and clicks Apply
Then the replacement is applied to every selected item's name in one transaction
```

```gherkin
When the user cancels or presses Escape
Then no names change
```

<task type="auto">
  <name>Task 2: Rename compute helper + BatchRenameDialog</name>
  <files>src/renderer/src/components/renameItems.ts, src/renderer/src/components/BatchRenameDialog.tsx</files>
  <action>
    renameItems.ts (pure, no React) — export:
      `type RenameSpec =
         | { mode: 'pattern'; template: string; start: number; pad: number }
         | { mode: 'replace'; find: string; replace: string; caseSensitive: boolean; regex: boolean }`
      `interface RenameInput { id: string; name: string; ext: string }`
      `function buildReplacer(spec): { error: string | null }` — for regex mode, `try { new RegExp(...) }`
        and return an error string on failure (so the dialog can show it / disable Apply).
      `function computeName(item: RenameInput, index: number, spec: RenameSpec): string`:
        - pattern: replace ALL `{name}`→item.name, `{ext}`→item.ext,
          `{n}`→`String(spec.start + index).padStart(spec.pad, '0')` (use split/join or a global regex).
        - replace: if `find` is empty → return item.name unchanged. Literal mode → replace all
          occurrences (case-sensitive via split/join; case-insensitive via an escaped global regex).
          Regex mode → `item.name.replace(new RegExp(find, caseSensitive ? 'g' : 'gi'), replace)`;
          on invalid regex return item.name unchanged (the dialog blocks Apply via buildReplacer).
      `function computeRenames(items: RenameInput[], spec): { id: string; name: string; oldName: string }[]`
        mapping computeName over items (index-based for {n}).

    BatchRenameDialog.tsx (mirror BatchTagDialog's backdrop/panel + self-owned Escape):
      props `{ items: RenameInput[]; onApply: (renames: { id: string; name: string }[]) => void; onClose: () => void }`.
      - State: a `RenameSpec` (default pattern `{name}`, start 1, pad 2) + a Pattern|Replace mode toggle
        (segmented control). Inputs per mode: Pattern → template + Start (number) + Pad (number);
        Replace → find, replace, Case-sensitive checkbox, Use-regex checkbox.
      - Compute `const preview = computeRenames(items, spec)` each render; show a scrollable old→new
        list (cap the rendered rows to ~50 with a "+N more" note; the apply still uses ALL).
      - If regex mode and `buildReplacer(spec).error`, show the error text and disable Apply.
      - Apply → `onApply(preview.filter(r => r.name.trim() && r.name !== r.oldName).map(({id,name}) => ({id,name})))`
        then onClose(). Enter triggers Apply (when enabled); Escape closes (stopPropagation).
      - A small "{name} {ext} {n}" token hint under the template input.

    Avoid: applying blank names; renaming files; a per-item manual edit field (that's the 07-07
    multi-item inspector); new deps.
  </action>
  <verify>npm run typecheck + npm run build clean; computeName handles pattern tokens + literal/regex replace; invalid regex returns an error from buildReplacer; preview filters blank/unchanged.</verify>
  <done>AC-1 + AC-2 preview/compute ready.</done>

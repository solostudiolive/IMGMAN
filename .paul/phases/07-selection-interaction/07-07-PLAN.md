<objective>
## Goal
Add an **editable multi-item inspector** shown when 2+ items are selected: an aggregate header
(count · total size · type breakdown) plus batch editors for **rating**, **tags**, and **folders**
that operate on the WHOLE selection — including showing the values **shared across all** selected
items (common rating / common tags / common folders) and removing them in one atomic write.

## Purpose
This is the final piece of the Phase-7 goal — "a polished editable collapsible inspector (single +
multi-item)". The single-item `Inspector` stays for a selection of one; a new `MultiInspector` takes
over for many. It reuses the 07-05 atomic batch IPC and adds the read/aggregate + batch-remove
channels needed to show and edit shared state.

## Output
- New IPC: `items:rateMany(ids, rating)`, `tags:commonForItems(ids)`, `tags:removeFromMany(ids, tagId)`,
  `folders:commonForItems(ids)`, `folders:unassignMany(ids, folderId)` (+ preload + `IpcApi`). Adds
  reuse the existing `tags:addToMany` / `folders:assignMany` (07-05).
- `MultiInspector` — token-styled panel: aggregate header; batch StarRating (shows "Mixed" when
  ratings differ, sets all); common-tag chips (removable) + add input; common-folder chips (removable)
  + add select.
- LibraryGate renders `MultiInspector` (selection > 1) vs `Inspector` (selection ≤ 1) in the shell's
  inspector slot.
</objective>

## Patterns to follow
- Backend: each batch mutation is one `db.transaction(...)` returning a count (mirror 07-05). Reads
  ("common") use a dynamic `IN (?,?,…)` built from ids + a `HAVING COUNT(DISTINCT item_id) = ?`
  (= ids.length) so only values present on ALL selected items are returned. Guard empty ids → []/0.
- Rating clamp 0..5 (mirror updateItem). No schema change; items_fts untouched.
- MultiInspector computes count / total size / type breakdown / common-rating RENDERER-side from the
  passed Item[] (free — the grid already has rating/size/type); it FETCHES common tags/folders via the
  new read channels. After any mutation: refetch the common lists + call onChanged (reload grid).
- Token styling only (var(--color-*) / radii / spacing) — do NOT copy TagEditor/FolderAssigner's hex.

      WHERE id = ?` per id, sum `.changes`.

    services/tags.ts —
      `commonTagsForItems(ids: string[]): Tag[]`: empty → []. Build `const ph = ids.map(()=>'?').join(',')`
        and run:
        `SELECT t.id, t.name, t.color FROM tags t JOIN item_tags it ON it.tag_id = t.id
         WHERE it.item_id IN (${ph}) GROUP BY t.id HAVING COUNT(DISTINCT it.item_id) = ?
         ORDER BY t.name COLLATE NOCASE` binding `...ids, ids.length`.
      `removeTagFromMany(ids: string[], tagId: string): number`: empty → 0; one transaction
        `DELETE FROM item_tags WHERE item_id = ? AND tag_id = ?` per id, sum `.changes`.

    services/folders.ts — mirror tags for folders:
      `commonFoldersForItems(ids): Folder[]` (JOIN item_folders/folders, same HAVING = ids.length).
      `unassignManyFromFolder(ids, folderId): number` (DELETE FROM item_folders WHERE item_id=? AND
        folder_id=? per id, in a txn).

    ipc/items.ts — `items:rateMany` → rateItems(ids, rating).
    ipc/tags.ts  — `tags:commonForItems` → commonTagsForItems(ids); `tags:removeFromMany` →
      removeTagFromMany(ids, tagId).
    ipc/folders.ts — `folders:commonForItems` → commonFoldersForItems(ids); `folders:unassignMany` →
      unassignManyFromFolder(ids, folderId).

    preload/types.ts + index.ts — add to IpcApi + the bridge:
      items.rateMany(ids, rating) → number;
      tags.commonForItems(ids) → Tag[]; tags.removeFromMany(ids, tagId) → number;
      folders.commonForItems(ids) → Folder[]; folders.unassignMany(ids, folderId) → number.

    Avoid: schema/ON DELETE CASCADE changes; touching files; altering existing single-item channels;
    SQL string interpolation of anything except the generated `?,?` placeholders (ids are bound).

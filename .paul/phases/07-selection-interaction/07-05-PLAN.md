<objective>
## Goal
Add **batch operations** over the current multi-selection: **delete** (remove DB rows + on-disk
files), **add a tag to many**, and **add many to a folder** — each as an ATOMIC main-side
transaction exposed via new IPC, surfaced through the 07-04 item context menu (selection-aware) and
a Delete keyboard shortcut.

## Purpose
This is the first Phase-7 plan to cross into main/preload/IPC + SQL. It turns the selection surface
(click/keyboard/marquee + context menus) into real bulk actions — the "batch operations" half of the
Phase-7 goal — using one transaction per operation so a large selection can't leave a half-applied
state.

## Output
- New services: `deleteItems(ids)` (txn: delete item_tags + item_folders + items, then remove each
  `images/<id>/` dir), `addTagToMany(ids, name)`, `assignManyToFolder(ids, folderId)` — all atomic,
  returning a count.
- New IPC: `items:delete`, `tags:addToMany`, `folders:assignMany` (+ preload + `IpcApi` types).
- LibraryGate: the item context menu becomes selection-aware (acts on the whole selection when the
  right-clicked item is part of a multi-selection, else on the single item) and gains **Delete N
  item(s)**, **Add tag…**, and a working **Add to folder ▸** that uses `assignMany`; the **Delete**
  key deletes the selection (with confirm).
- `BatchTagDialog` — a small token-styled modal (text input + datalist of existing tags) for the
  "Add tag…" action.
</objective>

## Patterns to follow
- Each batch op is ONE `db.transaction(...)` (mirror `deleteFolder`). Return a `number` count.
- FKs are NOT `ON DELETE CASCADE` (foreign_keys=ON), so delete MUST remove item_tags + item_folders
  links BEFORE the items row, all inside the txn. `items_fts` is unwired/unpopulated → ignore it.
- File removal (originals/thumbnails) is best-effort AFTER the DB txn commits: `rmSync(join(imagesDir
  (lib.path), id), { recursive: true, force: true })` per id, each wrapped in try/catch (DB is the
  source of truth; a leftover dir is harmless).
- IPC mirrors the existing triad: a service fn → `ipcMain.handle` in ipc/*.ts → preload method →
  `IpcApi` type. No throwing across IPC for expected cases (return counts).
- Modal keyboard-ownership (05-04): BatchTagDialog owns Escape + stops it reaching the global handler.
- Renderer reloads via the existing `reloadItems()` and clears selection after a delete
  (`sel.clear()`); the existing prune effect drops any stale ids.

<acceptance_criteria>

## AC-1: Delete selection (DB rows + files)
```gherkin
Given one or more items are selected
When the user picks "Delete N item(s)" from the item context menu, or presses the Delete key
Then a confirm prompt appears, and on confirm items:delete(ids) runs as a single transaction
And the items' rows (items + item_tags + item_folders links) and their images/<id> folders are removed
And the grid refreshes without them, the selection clears, and the inspector empties
```

## AC-2: Add a tag to many
```gherkin
Given several items are selected
When the user picks "Add tag…" and enters a tag name in the dialog
Then tags:addToMany(ids, name) runs in one transaction (creating the tag if new, INSERT OR IGNORE links)
And every selected item gains the tag (re-adding an existing tag is a no-op)
And selecting one of them shows the tag in the inspector
```

## AC-3: Add many to a folder
```gherkin
Given several items are selected and at least one folder exists
When the user picks "Add to folder ▸ <name>"
Then folders:assignMany(ids, folderId) runs in one transaction (INSERT OR IGNORE)
And selecting that folder in the sidebar shows all of them
```

## AC-4: Selection semantics + atomicity
```gherkin
Given a multi-selection
When the user right-clicks an item that IS part of the selection
Then the batch actions act on the WHOLE selection (labels show the count)
When the user right-clicks an item that is NOT part of the selection
Then that item becomes the single selection and actions act on just it
And each batch operation is a single main-side transaction (no partial application on a large set)
```

## AC-5: No regressions
```gherkin
When `npm run typecheck` and `npm run build` run
Then both pass with no new errors
And the 07-04 single-item menu (Quick preview / Rating), marquee (07-03), keyboard nav (07-02),
    and folder-delete-keeps-items (04-03) all still behave as before
And the SQLite schema file is unchanged (reuses existing tables)
```
